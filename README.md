# Игра «Тысяча»

## Описание проекта

Проект представляет собой реализацию карточной игры «Тысяча» на языке Java.

Программа состоит из библиотеки классов, реализующих игровую механику и аналитическую надстройку (сериализацию состояния в JSON, стратегии ботов с оценкой марьяжей, параллельную симуляцию серии партий и сбор статистики), а также консольного приложения для демонстрации работы.

## Используемые технологии

- Java 24
- Maven
- JUnit 5
- Jackson Databind (JSON)
- Git

## Правила игры

В игре участвуют три игрока. Используется колода из 24 карт: от девятки до туза в каждой из четырёх мастей.

Основные этапы раунда:

1. Раздача по семь карт каждому игроку и формирование прикупа из трёх карт.
2. Торговля игроков за право забрать прикуп (минимальный заказ — 100 очков, шаг — 5).
3. Передача прикупа победителю торговли и снос трёх карт.
4. Розыгрыш семи взяток с обязательным ответом в масть.
5. Объявление марьяжей (король и дама одной масти, начиная со второй взятки), которые приносят дополнительные очки и назначают козырную масть.
6. Подсчёт очков и проверка выполнения заказа.

Цель игры — первым набрать не менее 1000 очков.

В игре предусмотрены:
- **Очковый барьер 880**: игрок, не делавший заказ в раунде, не может подняться выше 880 очков за счёт взяток.
- **Штрафные «болты»**: за три подряд невыполненных заказа начисляется болт; при накоплении трёх болтов с игрока списывается 120 очков.

## Архитектура и структура проекта

Механика игры полностью отделена от консольного вывода: движок изменяет состояние партии и фиксирует происходящее в журнале событий. Надстройка третьего этапа расширяет функциональность без переписывания базовой механики:

- `model` — доменные объекты (`Card`, `Deck`, `Player`, `Bid`, `TrumpSuit`, `GameSettings`) и перечисления с полями (`Suit`, `Rank`).
- `engine` — игровая логика (`GameEngine`, `Dealer`, `Auction`, `TalonExchange`, `Trick`, `MarriageManager`, `RoundScorer`).
- `state` — реализация паттерна **State** для пошагового управления фазами раунда (`GameState`, `GamePhase` и состояния от инициализации до завершения).
- `events` — журнал игровых событий (`GameLog`).
- `rules` — константы правил игры (`GameRules`).
- `util` — компараторы для сортировки карт (`CardComparators`).
- `bot` — стратегии принятия решений игроками (`PlayerStrategy`, `DefaultBotStrategy`, а также `MarriageEvaluatingBotStrategy`, оценивающая руку с учётом готовых и потенциальных марьяжей).
- `storage` — сериализация и десериализация состояния партии и журнала в формат JSON (`GameSnapshot`, `GameStorage`), а также повтор партии из журнала без потерь.
- `simulation` — последовательная и параллельная симуляция серии из 1000 партий (`TournamentSimulator`) и агрегация статистики по заказам с использованием **Stream API** (`ContractStatistics`).
- `console` — консольное приложение (`Main`) для запуска демонстрационной партии и массовой симуляции.

## Запуск проекта

Для запуска необходимы JDK 24 и Apache Maven.

Сборка проекта и запуск через Maven:

```bash
mvn compile exec:java -Dexec.mainClass="ru.vsu.thousand.console.Main"
```

Также проект можно открыть в IntelliJ IDEA и запустить метод `main` в классе `ru.vsu.thousand.console.Main`. При запуске выполняются:
1. Демонстрационная партия с сохранением состояния в JSON и его восстановлением.
2. Параллельная симуляция 1000 партий с выводом сводной статистики по заказам и победам.

## Воспроизводимость

Все случайные операции (перемешивание колоды) используют единый экземпляр `java.util.Random`, инициализируемый параметром `seed` в `GameSettings`. При одинаковом значении `seed` ход партии полностью воспроизводится, а параллельный прогон серии партий в `TournamentSimulator` даёт результат, идентичный последовательному.

## Тестирование

Для запуска модульных и интеграционных тестов выполните:

```bash
mvn test
```

Тесты реализованы на JUnit 5 (83 тестовых сценария) и проверяют:
- правила игры на граничных ситуациях (барьер 880, три болта, марьяжи, снос, взятки);
- обработку недопустимых ходов и состояний;
- сохранение и загрузку партии в JSON и точный повтор позиции из журнала;
- оценку руки и принятие решений ботами с учётом марьяжей;
- параллельную симуляцию 1000 партий и подсчёт статистики через Stream API.
